# An instance is ready only while a self-test role works

A ping of the issuer login proves nothing about what the next connection needs: `CREATEROLE`, `ADMIN` on every group role, the group roles themselves and `CONNECT` on each database are checked only when a role is created, joined or logged in as, so a drift (a revoked grant, a Cloud SQL policy change) surfaced as failed connections behind a ready pod. So each instance is ready only after a self-test: create a temporary role with the statement real ones get, joined to every group role it could get (each database's read and write role, plus `statsRole`), log in as it to every served database, and remove it the way real roles are removed. It repeats every `selfTestInterval` (10m). Once ready, an instance turns not ready only after 3 failed checks in a row, one second apart, so one slow self-test does not empty the Service (the issuer ping on each `/readyz` stays, as before); one pass makes it ready again, and open connections are never touched. The self-test role carries the process's nonce, is never handed out, and one left by a crash is swept with the rest of a dead process's roles (ADR 0012).
